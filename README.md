# DOGFIGHTERS — Pixel Air Combat

Arcade biplane shooter in pixel art. Fills the whole browser window with whole-pixel scaling (reference view 320x180; wider windows show more sky). Phaser 3 + Node/Express + Socket.IO. Designed to be hosted on **Render** (not run locally) - follow **DEPLOY_RENDER.md** step by step. All sprites and sounds are generated by code — no external assets or APIs.

## Deploy on Render
**Option A - Blueprint:** push the repo to GitHub, Render -> New -> Blueprint, pick the repo (`render.yaml` is included).

**Option B - manual Web Service:** New -> Web Service -> pick the repo, then:
- Runtime: **Node**
- **Build Command:** `npm install`
- **Start Command:** `npm start`
- Health Check Path: `/health`
- Environment: `NODE_VERSION=20` (optional)

Things that matter for the room system on Render:
- **Run exactly 1 instance.** Rooms live in the server's memory; with 2+ instances two players could land on different servers and never see each other. (Scaling out later requires the Socket.IO Redis adapter + a shared room store.)
- **WebSockets** work on Render with no extra setup. The client connects to its own origin (`io()`), so there is no hard-coded URL.
- **Free plan sleeps** after ~15 min without traffic: the first visit can take ~1 min to wake; the menu shows OFFLINE until connected. A restart/deploy drops rooms (clients return to the menu with "CONEXAO PERDIDA").
- `PORT` is provided by Render. Optional `CORS_ORIGIN` is only needed if the front-end is hosted on another domain.
- SIGTERM (sent on deploy) is handled for a clean shutdown.
- Abuse guards: per-socket event rate limit, wrong-code throttling (6 tries / 30 s), max 500 rooms, max 30 connections per IP.

## Controls
- Mouse: move the crosshair; the plane always flies at constant speed toward the crosshair direction
- Left click (hold): machine gun fired toward the crosshair — 30 rounds, auto reload (2 s) at 0
- ENTER / SPACE / click: menu buttons

## Nickname and rooms
Menu: type a nick (3-16 chars: letters, numbers, inner spaces, `-` and `_`; trimmed; validated again on the server), then **JOGAR SOLO**, **CRIAR SALA** (5-char code) or **ENTRAR EM SALA**. The nick is kept in `sessionStorage`.
Identity is the Socket.IO connection (`socket.id`, never broadcast); nicknames are display-only, so duplicates are fine and host/start permissions are checked on the server. Events: `room:create`, `room:join`, `room:leave`, `room:start` (host only), `nick:change`; server pushes `room:update`, `room:event`, `room:started`. Rooms live in memory (max 4 players). ESC returns to the menu (leaves the room).
**Current limit:** when the host starts, every client launches the existing game locally; positions/bullets are not yet synchronised (see the multiplayer notes below).

## Going multiplayer (Socket.IO)
1. `npm i socket.io`; in `server.js` wrap `app` with `http.createServer(app)` and `new Server(httpServer)`.
2. Server is authoritative: keeps `players{id:{x,y,angle,hp,score}}`, `enemies[]`, and runs the same constants from `constants.js` (move them to a shared module).
3. Client sends input state (aim `x`,`y` in world coords, `fire`) ~20x/s; server simulates and broadcasts snapshots (~15-20/s). `Player` becomes local-predicted; other players are `RemotePlane` sprites interpolated between snapshots.
4. Bullets: send only fire events `{id, x, y, angle, t}`; each client simulates the tracer, and the server decides hits (`BulletPool` already stores previous position for swept hit tests) and emits `hit`/`kill`/`score` events.
5. Enemies spawn on the server and are sent in snapshots; clients only render them.
